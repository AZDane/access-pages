Hardened runtime evaluation with qURL 4.2.0 — 2026-11-19 UTC

Scope: independently evaluate the minimal Chainguard runtime while retaining
production application code, qURL 4.2.0, licenses, vulnerability baseline and
assessment deadlines. This branch starts from production ac55d0f, not PR #98.
It does not depend on the unavailable qURL 4.4.4 archive or approve a release.

Supply chain

The Python base is the official digest-pinned Chainguard Python image. Before
building, verify-base.sh verifies its publisher signature, architecture mapping
and both signed SBOMs. Its APK package metadata remains visible to scanners.

Only /usr/local/bin/qurl is copied from our already-published Access Pages
0.1.163 image, pinned to index 99259c306ff6b918249d5304202e7a64acd0e0c4a9a01eb7dba93cab9a9bd2cd.
The release's keyless signature must match our exact release workflow and tag,
with the GitHub OIDC issuer and transparency verification. The script verifies
its architecture manifests. Each build also checks the copied executable's
SHA-256 against the previously reviewed official 4.2.0 binary for that platform.
No Debian libraries, account files or runtime tools are copied from that image.
This is reuse of our signed released artifact, not a new LayerV download or a
locally rebuilt qURL. The original licenses and both qURL SBOMs are retained.

The timezone wheel comes from official PyPI with its pinned archive checksum.
The guest endpoint is built from unchanged application source in the existing
pinned official Go builder. The final image has no shell or package installer.
Eight service accounts retain their production IDs and use locked credentials
and nologin shells. The candidate AppArmor profile adjusts only Python paths
and its profile name. Existing UID separation and directory permissions apply.

Evaluation requirements

Run the native amd64 and arm64 packaged runtime, application, permissions,
TLS, startup, scheduling and qURL lifecycle probes. Run the application unit
suite and enforce AppArmor on the native amd64 CI runner, including executable
negative fixtures so absent commands cannot masquerade as policy denials.
Collect full Trivy inventories with every severity and no vulnerability ignores.
Bind image identities, provenance, SBOMs and actual APK inventories to the
independent OSV and original publisher-advisory evidence.

The 43 HIGH Debian package/advisory records in each production architecture
are separate from the qURL x/net finding. That finding appears three times in
the full report (the binary and two retained architecture SBOMs). qURL 4.2.0
still embeds x/net 0.61.0; its original bounded assessment is unchanged.

Earlier analysis of this base found 32 vendor/source advisory records covering
16 CVE IDs even though Trivy reported zero. The independent gate still rejects
unresolved records and all HIGH/CRITICAL scanner findings. No candidate waiver,
threshold reduction, scanner suppression or assessment renewal is introduced.
Successful functional tests alone cannot authorize promotion. A real HAOS
install/upgrade and live confined tunnel are additional acceptance evidence.

Independent advisory review

Official CVE records for all 16 IDs were retrieved on November 19 from the
CVEProject/cvelistV5 repository, alongside the original publisher records.
This review does not add any waiver or change the promotion gate.

Python (six IDs):
- CVE-2026-103995 affects HTTP response/chunk framing. A bounded in-memory probe
  shows that both candidate and production accept +1 and 0x1 chunk sizes, which
  are not valid HTTP hexadecimal chunk-size syntax. Access Pages uses this
  library in ha.py, policy.py, layerv.py, guest_resources.py, guest_service.py
  and ingress_proxy.py. Some calls are protected local broker connections;
  others contact configured upstreams over TLS. Application exploitation has
  not been demonstrated, but this cannot be dismissed as an unused module.
- CVE-2026-115559 affects imaplib STARTTLS. The actual installed starttls/readline
  methods preserve buffered plaintext after a mocked handshake in both images.
  Application source has no imaplib consumer. This is installed-library behavior,
  not a claim of an application-level exploit.
- CVE-2026-124249 affects shared CookieJar handling; no application CookieJar or
  HTTPCookieProcessor consumer was found. CVE-2026-19552 concerns
  ssl.get_server_certificate; no application call was found. These still need
  evidence-bound dispositions or vendor fixes before promotion.
- CVE-2026-16052 concerns attacker-controlled cookie attributes. Access Pages
  imports SimpleCookie, so input provenance needs specific review; do not infer
  safety from an import search alone.
- CVE-2026-115791 concerns the archive extraction CLI. No application invocation
  was found. The build extracts only the checksum-pinned timezone wheel using
  validated member names, and removes the preparation script afterwards.

OpenSSL (CVE-2026-88822, -88823, -95691, -95692, -107496):
The vendor's November 10 advisory rates these LOW and schedules releases with
fixes for December 1. The installed 4.0.3 libraries precede the cited 4.0.4 fix.
Affected paths are OpenSSL QUIC, AES-GCM-SIV and CMS encryption; Python TLS does
not itself establish their reachability, and qURL uses a separate static Go
TLS implementation. Configuration, symbol and call-path review are still needed.
https://openssl-library.org/news/secadv/20261110.txt

glibc (CVE-2026-100290, -115819):
The installed 2.44 is in the official affected ranges. These concern regex
allocation-error cleanup and wide scanf conversions. Their callers through
native libraries have not been exhaustively established; remain unresolved.

Expat (CVE-2026-124317, -128241):
The first concerns application-registered unknown encodings and requires native
consumer review. The second affects the xmlwf command-line program, which the
candidate does not contain. Preserve the source match while documenting the
component distinction; do not suppress the whole Expat package.

SQLite (CVE-2026-119586):
The described attack requires the sqlite3 CLI .recover output being piped into
the shell. The candidate has the shared library but neither sqlite3 CLI nor an
OS shell. This source-package match is a candidate for an absent-component
assessment, not evidence that all SQLite issues are absent.

The public Chainguard Python latest tag was checked again during this evaluation
and still resolves to the pinned index. No newer patched image was available
through that tag. Do not replace these stable libraries with unreleased source
builds or mix distribution libraries to make the scanner count disappear.

Reproducible observations are in tests/packaged_advisory_observations.py. CI runs
them offline and read-only on both native architectures and retains their JSON.
The diagnostic does not approve or waive findings. Both the independent advisory
gate and the runtime behavior gate below must pass for promotion. Production code, qURL and review dates are unchanged.

Blocking runtime advisory checks (November 19 follow-up)

Previously the Python observations were retained only for manual review. The
security/check_runtime_advisories.py gate now rejects either reproduced defect
regardless of scanner output, severity or vulnerability-baseline entries. It runs
inside the actual immutable image, offline, read-only and without capabilities,
and records image identity, architecture, probe hash and installed-library hashes.
Missing/malformed results, wrong architecture, failed valid-input controls and
probe execution errors all block. Raw observations and the decision are retained.

Coverage includes invalid signs, prefixes, underscores and leading whitespace in
HTTP chunk sizes; invalid Content-Length syntax; valid chunk extensions and
optional Content-Length whitespace; and IMAP buffering across STARTTLS. The IMAP
probe accepts the official fix's abort before TLS when plaintext remains buffered.
These are library regression checks, not proof of application exploitability.

Both native CI architectures run this gate for standalone, production App and
hardened images. The release workflow checks both retained release images before
registry login or publication. The existing protected Container image aggregate
still requires successful package and candidate jobs. Scheduled security checks
now run daily; schedules take effect only once this branch is merged. Existing
scanner settings, 16-CVE independent candidate advisory gate, baseline review
dates and evidence requirements are unchanged. This does not detect every unknown
library defect or add the Chainguard-specific advisory inventory to Debian.

Local validation rejected both the signed production v0.1.163 image and the
hardened candidate for the known defects. An isolated positive-control run with
unaltered official CPython modules passed all 15 behavior checks:
- HTTP: Python 3.15 backport 5b9e3d044764cf59329fb8147177f54a88d1fb49
  https://github.com/python/cpython/pull/159021
- IMAP: 2f0e294d85c905691e360586ebd1d1f7e7a1f5df
  https://github.com/python/cpython/pull/160370
These modules were used only in a disposable offline test, not installed in any
application image. The runtime fixes themselves remain separate work.

Remaining advisory triage and patch choices:
- http.cookies.Morsel output injection (CVE-2026-16052): application SimpleCookie
  use parses the inbound cookie and reads token.value; it does not emit Morsel
  output. The outgoing Set-Cookie header is constructed separately from validated
  server-issued values. This supports further bounded applicability review, not
  a blanket exception based on a SimpleCookie import.
- CookieJar (CVE-2026-124249), ssl.get_server_certificate (CVE-2026-19552), archive
  extraction CLI (CVE-2026-115791): no application consumer found in current source.
  Source changes and indirect library consumers must remain part of the review.
- SQLite CLI .recover (CVE-2026-119586), xmlwf (CVE-2026-128241): the affected CLI
  components are absent from the candidate. Shared libraries remain inventoried.
- OpenSSL five IDs: the affected QUIC, CMS and AES-GCM-SIV paths are distinct from
  Python's ordinary TLS use. qURL uses its static Go TLS implementation. Native
  call/configuration review remains necessary. Prefer a vendor package backport;
  do not transplant libraries from another distribution or rebuild cryptography
  merely to improve scanner output.
- glibc two IDs and Expat unknown-encoding callback (CVE-2026-124317): native
  consumer evidence remains incomplete. Prefer vendor-supported package fixes;
  local compiled-library replacements would require ABI and upstream-suite work
  well beyond these small, verifiable Python changes.

Live tunnel acceptance and real HAOS install/upgrade/rollback remain required.
The qURL 4.2.0 built-in get help defines exit 11 as temporary link unavailability;
this explains the category, not its underlying service cause. Existing control
